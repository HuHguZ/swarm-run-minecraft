# IdeasProbe: пассивный server receipt

Отдельный временный Bukkit plugin для слота28. MONITOR `ProjectileLaunchEvent` для `ThrownPotion` стрелка `NeuroFarm28b0`, `PlayerMoveEvent` этого игрока. `EntityDamageByEntityEvent` записывается только при server port25628, от exact `NeuroFarm28b0` или `NeuroFarm28j` к Player с именем prefix`NeuroFarm28`. Дополнительно MONITOR `ServerTickEndEvent` и `EntityDamageEvent` с cause FALL только при server port25628 и exact player`NeuroFarm28b0`. Обработчики не меняют событие, движение, сущности или соединение; команд, scheduler и Netty hooks нет. Gson и Paper API берутся из уже имеющихся библиотек сервера, новые зависимости не устанавливаются.

При загрузке пишет/добавляет `plugins/IdeasProbe/events.jsonl` сервера, flush после каждого receipt. Поля каждой строки: `event`, native server `tick` (`Bukkit.getCurrentTick()`), wall `ms`, `player`, `world`, `playerpos`, `onGround`, `fallDistance` (native double NMS field), `knownMovement`, `connection.{awaitingPositionFromClient,awaitingTeleport,hasClientLoaded,clientLoadedTimeoutTimer,waitingForRespawn,justTeleported,hasMoved,lastPosX,lastPosY,lastPosZ}`. У `potion_launch` также `entityId`, `cancelled`, `launchpos`, native `velocity`; у `player_move` — `from`, `to`, `cancelled`, `pendingChanged`. Векторы копируются числами сразу на потоке события; `null` pending position сохраняется явно, ошибка reflection обозначается `{"unknown":"..."}`, не ложным `false`/`null`.

Движение логируется только при изменении Y или состояния pending/loaded; первый move тоже записывается как начальный снимок. `PlayerMoveEvent` показывает from/to и cancellation в фазе MONITOR: это receipt события, не гарантия окончательного commit после чужих обработчиков. `ProjectileLaunchEvent` показывает состояние при создании снаряда; само по себе оно не устанавливает, какая прежняя ветка обработчика отклонила movement. Оба события включают cancelled-вариант для различения отмены и принятого запуска.

`mace_damage` добавляет `cancelled`, `damageTypeKey`, `rawDamage`, `finalDamage`, `attackerId`, `targetId`, `target`, `targetpos`, `targetOnGround`, `targetHpPre`. Имя события не фильтрует оружие: ordinary melee b0 также записывается; smash различается по native `damageTypeKey`, например `minecraft:mace_smash`. `rawDamage` — текущий `event.getDamage()` в MONITOR, `finalDamage` — `getFinalDamage()`, а не обещание ещё не произошедшего HP delta. `targetHpPre` и все серверные поля — только файл телеметрии фермы; бот их не получает.

Порядок local Paper1.21.11: `Player.attack` сначала вычисляет item bonus/crit, затем вызывает `hurtOrSimulate` (saved `codex-lab/ideas/jar/Player.javap.txt`:2390–2424,2452), после возврата вызывает item interaction; `ItemStack.postHurtEnemy` вызывается позже (2794), а `MaceItem.postHurtEnemy` сбрасывает fallDistance (`MaceItem.javap.txt`:198–205). Поэтому snapshot в damage event — **captured fall после вычисления bonus, до штатного mace post-reset**, а не RCON после удара. Если другой plugin меняет состояние в damage callbacks, snapshot не восстанавливает прежний bonus input. Для принятого попадания нужны cancelled=false, полезный finalDamage и сопоставленный native damage/HP receipt; само событие с cancelled=true/нулём не считается уроном.

H38 `player_tick_end` пишет общий snapshot после tick processing и добавляет `isInWater`, `hp`, `velocity`, `feetBlockData` и `sourceBlockData` фиксированной клетки(600,151,597) в текущем world игрока. Source chunk(37,37) сначала проверяется через isChunkLoaded; при отсутствии пишется `unloaded`, загрузка не запрашивается. Bukkit `Player.isInWater()` здесь напрямую делегирует NMS `Entity.isInWater()` (CraftEntity1.21.11); это native water flag, а не вывод по блоку под ногами. `ServerTickEndEvent` показывает уже committed состояние к этому callback, но не восстанавливает каждый промежуточный move внутри tick. Поля только записываются в файл, ботам не передаются.

`fall_damage` пишет cause`FALL`, `cancelled`, `rawDamage`, `finalDamage`, `hpPre`, `isInWater` и общий snapshot B0 в MONITOR. Это состояние до применения итогового HP delta и штатного landing reset; сопоставлять с последующим `player_tick_end` и observer damage_event. Вода в source cell, пустое ведро, один water flag или h0 после onGround по отдельности не доказывают catch: h сбрасывается и после уже нанесённого fall damage. Нужен временной ряд water contact/h reset до ground и фактический HP результат.

Команды создают только `farm/swarm/combo-probe/out`. Укажи JDK 21 в `JAVA_HOME`.

```powershell
$javaTask = Join-Path $env:JAVA_HOME 'bin/java.exe'
$sourceTask = Join-Path (Get-Location) 'farm/swarm/combo-probe'
$outTask = Join-Path $sourceTask 'out'
$classesTask = Join-Path $outTask 'classes'
$classpathTask = (Get-ChildItem -LiteralPath 'server-run/libraries' -Recurse -Filter '*.jar' | ForEach-Object FullName) -join ';'
New-Item -ItemType Directory -Force -Path $classesTask | Out-Null
& $javaTask -m jdk.compiler/com.sun.tools.javac.Main --release 21 -proc:none -encoding UTF-8 -cp $classpathTask -d $classesTask (Join-Path $sourceTask 'IdeasProbe.java')
if ($LASTEXITCODE -ne 0) { throw 'IdeasProbe javac failed' }
& $javaTask -m jdk.jartool/sun.tools.jar.Main --create --file (Join-Path $outTask 'IdeasProbe.jar') -C $classesTask . -C $sourceTask plugin.yml
if ($LASTEXITCODE -ne 0) { throw 'IdeasProbe jar failed' }
```
